# 2.0.0 rollout runbook

The operator checklist for taking 2.0.0 from the dev branch to the live server (GodlessEmpire on
AMP, players on Thunderstore Mod Manager). Written 2026-08-10. The soak protocol at the end is
the one recorded in [2.0-followups.md](2.0-followups.md) and is part of the release gate.

## 1. Pre-publish checklist (repo)

- [ ] The three version declarations agree: `src/ChestButler/Plugin.cs` (`ModVersion`),
      `src/ChestButler/ChestButler.csproj` (`<Version>`), `pkg/manifest.json`
      (`version_number`). `build.sh` refuses to build if they drift.
- [ ] `pkg/CHANGELOG.md` has the 2.0.0 entry at the top.
- [ ] `pkg/README.md` is the 2.0 rewrite (processors-only station table, sign syntax with
      area-off, the "Before your first Organize" protection section, Gather, Sorter Chest).
- [ ] `pkg/manifest.json` dependencies match what we actually test against:
      `denikson-BepInExPack_Valheim-5.4.2333`, `ValheimModding-Jotunn-2.29.2`,
      `MSchmoecker-MultiUserChest-0.6.1`.
- [ ] Fresh `./build.sh` passes and the test suite is green (`tests/OrganizePlannerTests`).
- [ ] `pkg/ChestButler.dll` is the freshly built 2.0.0 DLL (copy from `dist/`), not a stale one.
- [ ] The Thunderstore zip contains exactly, at the zip root: `manifest.json`, `icon.png`,
      `README.md`, `CHANGELOG.md`, `LICENSE`, `ChestButler.dll`.
- [ ] Release commit on dev, tagged `v2.0.0`.

## 2. Publish (owner action)

- Upload the zip at https://thunderstore.io/c/valheim/ under the EK_Solutions team.
- Check the rendered README and changelog on the package page before telling anyone.
- Do not update the server profile code yet; do that as part of the rollout below so nobody
  gets 2.0 before the server has it.

## 3. Prod rollout

The version handshake (Jotunn, minor strictness) means a 2.0 server refuses 1.1.x clients and
a 1.1.x server refuses 2.0 clients. There is no mixed state, so the whole group moves together.

1. **Pick a time with the group.** Everyone updates in the same window; anyone who doesn't
   gets a clear connect error until they do.
2. **Back up the world.** Full AMP world backup. Keep the 1.1.2 DLL next to it. This is the
   rollback point.
3. **Config review on the server, before the update.** Open the live
   `eksolutions.chestbutler.cfg` and compare against the new defaults. Specifically:
   - `Radius`: the live server had it at 32 at one point; 2.0's default and tested value is 128.
   - `[Stations]`: lines for crafting stations (forge, workbench, cauldron) become inert in
     2.0. If the group wants any of them back, move them to `CustomStations`.
   - `[Organize] MovesPerTick` no longer exists; the new keys are `MovesPerSecond` and
     `MaxMovesPerRun`. Delete the stale key or leave it, it is ignored either way.
4. **Update the server.** Replace `ChestButler.dll` in the server's `BepInEx/plugins/` via the
   AMP file manager. Jotunn stays at 2.29.2 and MultiUserChest at 0.6.1, no change needed.
5. **Update the profile code.** Refresh the shared r2modman/TMM profile so **Import / Update**
   pulls 2.0.0, then tell the group to update before their next session.
6. **First login (owner):** wait for the base to finish loading (about a minute), then run one
   Organize and check the log line. The census count should be stable across the preview and
   the confirm, and the skip breakdown should be empty or name only small residue.

## 4. Soak protocol (first week on prod)

- **Sorter Chests: hold off placing them during the soak week.** They are a custom prefab.
  Rolling back to 1.1.2 deletes placed ones (the game removes unknown prefabs on load), along
  with their contents. Everything else survives a rollback; the new ZDO keys are just ignored.
- **One person presses Organize at a time.** Two simultaneous runs from different players is
  the one path with no code-level arbitration (a claim stamp is deferred to 2.1 by design).
  The failure mode is churn rather than loss, but do not invite it in week one.
- **Debug logging ON** on the server and on the owner's client for the week. After sessions,
  skim for: "timed out", "skipped", "Declined", "RespFailed", "unverified", repeated
  "[throttle]", and any "Organized N" that disagrees with the preview number.
- **Tell the group:** if items ever seem to vanish, say so immediately and name the chest
  location. The log will show the move.
- **After a clean week:** Debug off, soak over, 2.1 planning starts.

## 5. Rollback plan

If something serious surfaces during the soak:

1. Announce, then restore the world backup from step 3.2 (players lose progress back to the
   backup point; that is why the backup happens immediately before the update).
2. Put the 1.1.2 DLL back on the server and revert the shared profile code.
3. Sorter Chests placed against the advice above are lost by the restore or prefab removal;
   their contents existed after the backup point and go with them.
4. File what broke in docs/, fix on staging, and re-run this runbook.
